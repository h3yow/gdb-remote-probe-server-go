# 远程调试探针：协议、镜像与会话说明

本项目用**本地可复现的镜像与执行模型**替代真实硬件、调试器探针与外部
服务：镜像由进程内的 `pkg/image` 解析，目标是 `pkg/target` 中的小型受保护
内存虚拟机，串行调试协议由 `pkg/protocol` 实现，会话/能力协商/独占互斥由
`pkg/session` 负责。验证全程不依赖真实调试器、硬件或固定时长睡眠。

---

## 1. 目标镜像格式（pkg/image）

自定义、自描述格式（魔数 `RDPIMG01`，小端，尾部 CRC-32/IEEE），无需 ELF
工具链。字段：版本、入口、标志、构建时间、32 字节 BuildID、内存区表、
符号表。

- **内存区**：名字、地址、长度、权限（`r`/`w`/`x`）、数据。
  - 可执行区必须 4 字节对齐；区之间不得重叠；权限不得为空。
- **符号表**：名字 + 地址 + 大小，名字唯一。
- **裁剪标志**：置位时符号表被整体省略，但镜像仍可完整加载和调试。
  此时解析符号返回可区分的 `ErrSymbolNotFound`。

### 1.1 加载错误（互不相同，可 `errors.Is` 判定）

| 错误 | 触发条件 |
| --- | --- |
| `ErrBadMagic` | 魔数不是 `RDPIMG01` |
| `ErrUnsupportedVer` | 版本号非当前版本（CRC 仍需正确） |
| `ErrTruncated` | 文件短于头部/区表/符号表所需长度，或计数越界 |
| `ErrCorrupt` | CRC-32 不匹配，或解析后存在尾部多余字节 |
| `ErrBadRegion` | 空权限、空区、可执行未对齐、越界、区重叠 |
| `ErrBadSymbol` | 空符号名、符号重名 |
| `ErrSymbolNotFound` | 查询的符号不存在（含裁剪镜像） |

`Load` 是纯函数：相同字节总是得到相同、独立（深拷贝）的视图；同一镜像
重复加载、或断线重连后重新加载，内存布局/权限/符号视图一致。

## 2. 串行调试协议（pkg/protocol）

### 2.1 帧格式

```
数据帧:   '$' <body> '#' <hexHi> <hexLo>     校验和 = body 字节和 mod 256
控制字节: '+' 确认   '-' 否认(请求重传)   0x03 异步中断
```

- `Decoder` 按字节流重组，支持**半包**（任意分块送达）、帧间噪声跳过、
  非法校验位报 `ErrFrameBad`、校验不符报 `ErrChecksum`，随后从下一个
  `'$'` 重新同步，后续帧不受影响。
- `Pipe` 是进程内可损伤传输，可确定性地制造：
  丢首帧、翻转校验位（触发对端 `-`）、整帧重复、按字节拆包（半包）、
  暂停（帧本地成功但不投递，用于超时重传）。

### 2.2 确认、重传、重复与迟到 ACK

`Link` 为每条连接运行**独立的读/写协程**与单一帧转发通道：

- **确认**：收到完整帧立即回 `+`；校验错误回 `-`。
- **重传**：发送方等本帧的 `+`；收到 `-` 或超时后重发**完全相同**的帧。
  超时次数耗尽返回 `ErrTimeout`。
- **重复包**：仅当“上一帧尚未被应用层取走”且字节完全相同才判定为重传，
  再次 `+` 但不重复交付；一旦上一帧已交付，内容相同的新命令仍正常交付。
- **迟到/陈旧 ACK**：`+` 只与“当前在飞的 Send”配对；没有在飞 Send 时
  到达的 `+` 被丢弃，绝不可能满足下一条无关命令。
- **半包/迟到确认**：超时与 ACK 用每帧独立的等待通道配对，支持虚假唤醒，
  不会因确认迟到而错乱。

### 2.3 报文异常

- 校验失败：接收方 `-`，发送方重传；最终失败返回 `ErrTimeout`。
- 帧残缺/校验位非法：`Decoder` 给 `ErrFrameBad` 并自动重同步。
- 连接关闭：阻塞的 `Recv`/`Send` 经 `Done` 与错误返回收敛到 `ErrClosed`。

## 3. 会话与能力协商（pkg/session）

### 3.1 握手（强制）

连接建立后**必须**先发 `qSupported:...`，否则服务器回 `E03` 并拒绝连接
（`ErrCapabilityRejected`）。能力项形如 `name+` / `name-` / `name=value`：

- 服务器通告：`swbreak+`、`hwbreak+`、`qXfer:memory-map+`、`qRcmd+`、
  `PacketSize=400`。
- **协商不一致**：
  - 可选项（memory-map、qRcmd）未提供或显式拒绝 → **降级**，相关查询
    返回空响应（gdb 语义的“不支持”），连接继续。
  - 必需项 `hwbreak` 在 **StrictCaps** 下被显式 `hwbreak-` 拒绝 →
    回 `E02` 并断开（明确拒绝而非静默继续）。

### 3.2 独占会话

一个 `Server` 同一时刻只接受一个活动会话（一个目标）：

- 第二个并发 `ServeConn` 立即返回 `ErrSessionBusy`，**不交错执行**任何
  请求，也不会触碰新传输。
- 会话结束（detach `D`、断连、空闲超时）后释放目标锁，服务器可接受新
  会话；目标视图（寄存器/内存/断点）在同一目标上保持，可重连验证。

### 3.3 命令集与回复

| 请求 | 含义 | 成功回复 |
| --- | --- | --- |
| `qSupported:...` | 能力协商 | 能力列表 |
| `?` | 停机原因 | `Sxx[;reason:...]` |
| `g` / `p<n>` / `P<n>=<v>` | 寄存器读 / 单读 / 写 | hex / `OK` |
| `m<a>,<n>` / `M<a>,<n>:<hex>` | 内存 hex 读 / 写 | hex / `OK` |
| `X<a>,<n>:<binary>` | 二进制内存写 | `OK` |
| `Z1,<a>,<k>[;th=<n>][;cond=<hex>]` | 设硬件断点（可带阈值/条件） | `OK` |
| `z1,<a>,<k>` | 清硬件断点 | `OK` |
| `qBp` | 断点状态表（地址/启用/命中/停住/阈值/条件） | `bp:<rec>;...` |
| `qBpEn,<a>` / `qBpDis,<a>` | 启用 / 禁用断点 | `OK` |
| `qBpCfg,<a>[,th=<n>][,cond=<hex>]` | 原子改条件/阈值 | `OK` |
| `qBpBatch,<spec>;...` | 原子批量设断点 | `OK` |
| `s` / `c` | 单步 / 继续 | `Sxx[;reason:...]`（c 的停机回复异步发送） |
| 0x03（Ctrl-C） | 异步中断运行 | `S02;reason:pause` |
| `qSymbol:<hexname>` | 符号解析 | `<hexname>:<hexaddr>` |
| `qXfer:memory-map:read` | 内存映射（需协商） | XML，或降级为空 |
| `qRcmd,<hex>` | 远程命令（`reset`） | `OK` |
| `D` / `k` | 分离 / 结束 | `OK` 后断开 |

运行中（`c` 已开始、尚未停机）到达的普通命令一律回 **`E10`** 拒绝，不
执行；只有 0x03 被接受并触发中断。会话主循环是入站帧的**唯一消费者**，
运行/停机切换不会产生双重读取或命令交错。`c` 的启动是同步到“目标已
进入 running”才记录日志的，因此紧随其后的 Ctrl-C 不会落在启动空窗里
而丢失中断。

### 3.4 停止回复（Sxx 扩展）

停止回复以 `Sxx` 开头（保持 gdb 信号语义与旧客户端兼容），后接
`;key:value` 扩展字段细分原因，客户端无需额外往返即可区分：

| 回复 | 含义 |
| --- | --- |
| `S05;reason:bp;addr:<hex>;hits:<n>` | 普通动态断点命中（第 n 次到达） |
| `S05;reason:condbp;addr:<hex>;hits:<n>` | 条件/阈值断点真正停住 |
| `S05;reason:brk;addr:<hex>` | 镜像内静态 `BRK` 指令 |
| `S05;reason:step` | 单步完成 |
| `S02;reason:pause` | 运行中被外部中断（Ctrl-C） |
| `S00;reason:exit` | `HALT`，目标终止 |
| `S0b;reason:fault;code:<name>` | 内存/解码故障 |

“条件不成立 / 命中次数未到而**没有停**”不产生停止回复：目标继续执行，
客户端通过 `qBp` 状态表观察到 `hits` 增长而 `stops` 不变（差值即跳过
次数），据此与真正的停住区分。

### 3.5 错误码（Exx，互不相同）

| 码 | 含义 | 码 | 含义 |
| --- | --- | --- | --- |
| `E01` | 通用错误 | `E22` | 地址未 4 字节对齐 |
| `E02` | 能力协商被拒绝 | `E23` | 访问越界/未映射 |
| `E03` | 首包不是 qSupported | `E24` | 权限不足（只读等） |
| `E10` | 目标运行中，命令拒绝 | `E30` | 断点槽位已满（4 个） |
| `E11` | 目标已终止 | `E31` | 断点地址冲突 |
| `E20` | 非法寄存器号 | `E32` | 清除不存在的断点 |
| `E21` | 写只读寄存器（r0） | `E33` | 断点地址非可执行代码 |
| `E34` | 断点条件表达式非法 | `EFF` | 未知命令 |
| `E40` | 符号不存在 | | |

### 3.6 兼容范围

- 停止回复始终以 `Sxx` 开头，只识别前 3 字节的旧客户端行为不变；扩展
  字段（`;reason:...`）可安全忽略。注意外部中断现在回 `S02`（旧版回
  `S05`），需要区分中断与断点的客户端应读取 `reason` 字段。
- 旧版 `Z1,<a>,<k>` 三段格式不变；`;th=`/`;cond=` 后缀为可选扩展，
  旧客户端不会发出。重复 `Z1` 同一地址仍是幂等 no-op（命中计数保留），
  但带后缀的重复设置会按新规格替换条件/阈值。
- `qBp*` 系列为自定义扩展命令；不支持的客户端不发送即可，不影响其他
  命令。条件表达式语法是本实现自定义的（非 gdb 表达式），仅支持
  第 4 节所述文法。
- 断点容量固定为 4（`MaxBreakpoints`），批量请求的容量按“已装 + 新增
  去重后”的合计计算。

## 4. 执行控制与一致性（pkg/target）

- 16 个 32 位寄存器，`r15` 为 PC，`r0` 硬连线为 0（只读）。
- 指令：`HALT/MOVI/MOVR/ADD/ADDI/LOAD/STORE/JMP/JZ/BRK`。
- **单步**：精确执行一条指令；当前 PC 处的硬件断点在单步时被越过一次且
  不计命中。
- **继续**：运行到动态断点、静态 `BRK`、`HALT`、内存/解码故障或中断。
  从断点停机恢复时自动越过当前断点一次（硬件 resume 语义），循环回该
  断点时再次命中并累加命中计数。
- **原子失败**：内存写在落盘前完成全部越界/对齐/权限检查，被拒绝的写
  （含跨区、只读）绝不改动任何字节；寄存器写同样先校验。
- **断点**：上限 4 个槽位（`MaxBreakpoints`），越限/非代码/未对齐分别
  返回不同错误，且越限请求不影响已设断点。set/clear 幂等语义清晰
  （重复 set 为 no-op 且保留命中数；clear 不存在的地址返回
  `ErrNoBreakpoint`）；反复设置/清除结果稳定一致。
- **条件与命中阈值**：每个断点可带一个条件表达式和一个命中阈值。
  到达断点（启用状态下）先累计 `hits`，再判定：条件成立（无条件视为
  成立）且 `hits >= threshold`（`threshold = 0` 表示无阈值）才真正停住
  并累计 `stops`；否则跳过继续执行，绝不误停。`hits - stops` 即跳过
  次数。判定发生在指令执行前，因此停住时该指令尚未执行。
- **条件表达式**：`cmp (&& cmp)*`，`cmp` 为 `项 比较符 项`；比较符
  `== != < <= > >=`；项可以是寄存器 `r0..r15`/`pc`、立即数（十进制或
  `0x` 十六进制）、内存字 `u32[地址]`（4 对齐）。配置时即完成解析，
  非法表达式返回 `ErrBPBadCond`（线上 `E34`）；求值时内存不可读按
  条件不成立处理（继续执行），不会故障停机。
- **断点管理原子性**：启用/禁用（`EnableBreakpoint`）、改条件/阈值
  （`ConfigureBreakpoint`）、批量设置（`ApplyBreakpoints`）都在校验
  全部通过后一次性提交；任何一项不合法（地址、条件语法、批量合计超
  容量）整体拒绝，断点表保持原状，不留半成品。改条件/阈值保留命中
  计数。
- **中断**：`Interrupt`/`context.Cancel` 阻塞到执行循环真正停在指令边界，
  状态确定为 paused；重复中断幂等。
- **复位**：`Reset`/`qRcmd reset` 恢复镜像原始字节、清零寄存器、
  PC=入口、清空断点与命中计数。
- 指令预算默认 `1<<20` 作为失控保护；可 `SetInstructionBudget(0)` 设为
  无限（仅由陷阱/中断停止），用于循环中断测试。

停机原因 `Reason` 在目标层细分为：`pause`（外部中断）、`breakpoint`
（普通断点/静态 BRK）、`cond-breakpoint`（条件/阈值断点停住）、
`step`、`terminated`、`fault`；线上映射见 3.4 停止回复表。

## 5. 会话与断点生命周期、终态收敛

- **会话**：打开 → qSupported → 命令循环 → `D`/断连/超时；断连或超时后
  运行中的目标被确定性中断并停在指令边界，会话锁释放，服务器可再接入。
- **空闲超时**：静默超过 `IdleTimeout` 关闭会话并返回 `ErrIdleTimeout`。
- **断点**：随目标存活（跨会话保持）；重复设置不占新槽，清除幂等；
  目标 `Reset` 清空。断连再重连后，新会话通过 `qBp` 读到的是同一份
  断点表：地址、启用状态、命中/停住计数与断连前完全一致（目标对象
  共享，无隐藏残留、无计数错乱）；需要清零时用 `qRcmd reset` 显式复位。
  会话层在日志中打印每次断点变更与槽位占用。

## 6. 本地验证方法（无真实硬件/调试器/外部服务）

```bash
# 全部单测，竞态检测，多次重复（结果确定，不依赖固定睡眠）
go test ./... -race -count=10

# 查看报文 / 会话状态 / 拒绝原因日志
go test ./pkg/session/ -race -v

# 脚本化端到端演示（构建镜像→加载→协商→断点/单步/继续/中断/分离）
go run ./cmd/probe
```

- 正常链路用真实时钟的 25ms ACK 兜底，但测试逻辑由字节事件驱动，
  **不 sleep 等待**；重传/超时测试使用 `clock.FakeClock` 与
  `WaitForTimers`/`AdvanceToNext` 精确推进时间，无竞态忙等。
- 覆盖：畸形报文、半包、噪声、校验失败重传、丢帧超时重传、重复包抑制、
  迟到 ACK、并发第二会话拒绝、裁剪镜像、只读写、越界、断点上限/对齐/
  非代码、运行中命令拒绝、Ctrl-C 中断、空闲超时、断线重连视图一致。
- 断点增强覆盖（`pkg/target/breakpoint_test.go`、`cond_test.go`、
  `pkg/session/breakpoint_test.go`，日志含 `scenario=`/`expect=`/
  `actual=` 便于核对每个场景的期望与实际）：
  条件表达式解析/求值（寄存器、内存、越界内存按不成立）、条件成立才停、
  条件不成立跑到 HALT、命中阈值停住与阈值后每次停、禁用断点不计命中、
  启用/禁用/改条件失败的原子性、批量请求一项非法整批拒绝、容量上限
  不影响已设断点、反复设置/清除结果稳定、并发管理操作竞态稳定、
  停止回复原因细分（bp/condbp/brk/step/pause/exit/fault）、
  断连重连后断点表/启用状态/命中计数一致。
