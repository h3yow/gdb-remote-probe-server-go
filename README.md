# gdb-remote-probe-server-go

一个**完全本地可复现**的远程调试探针服务。它用自定义的虚拟目标机和确定性
镜像/执行模型代替真实探针硬件，实现了 GDB Remote Serial Protocol（RSP）的
服务端子集，使下列场景在并发会话、异常报文与非法操作下始终保持
**内存 / 寄存器 / 断点状态一致且可解释**：

- 并发调试会话争用（同一目标同一时刻只允许一个活动会话）；
- 半包、校验错误、重复包、迟到确认、超时重传；
- 越界访问、只读写入、断点越界 / 未对齐 / 超上限、运行中操作；
- 断线重连、空闲超时、被裁剪（stripped）镜像。

验证过程**不依赖真实调试器、探针硬件或任何外部服务**，结果确定，且可在
`-race` 竞态检测下稳定通过。

---

## 1. 目录结构

| 包 | 职责 |
| --- | --- |
| `pkg/target` | 镜像文件格式与校验、段/权限/符号、虚拟目标机（寄存器/内存/指令集）、断点与执行控制 |
| `pkg/protocol` | RSP 帧层（`$...#cc`、`+/-`、重传）、命令分发、能力协商、可控时钟 |
| `pkg/session` | 目标装载池、单活动会话互斥、Detach/Kill 生命周期与终态收敛 |
| `pkg/server` | TCP 接入、协议主循环、continue/中断编排、冲突拒绝、报文与状态日志 |
| `cmd/probe` | 命令行：`init-image`（生成样例镜像）、`serve`（启动服务） |

## 2. 协议覆盖面

实现的是 GDB RSP 的一个自洽子集（报文均为标准 `$body#checksum` 帧）。

### 2.1 帧层（`pkg/protocol`）

- **帧格式**：`$<body>#<xx>`，两位十六进制校验和（body 字节和 mod 256）。
- **确认**：标准 ack 模式下，收到正确帧回 `+`，校验错误回 `-`；发送方等
  `+`，超时按 `MaxRetransmit` 次重传，仍无确认则返回可区分的超时错误。
- **半包**：解析是严格逐字节状态机（`idle / body / sum1 / sum2`），帧可在
  任意字节边界拆分后重组。
- **重复包**：帧层把重传的同序帧照常上送；**会话层**对“紧邻的上一条已答复
  同步命令”做幂等回复重放（不重复执行副作用）。异步继续包 `c` 不参与重放，
  因为它代表一次新的状态迁移。
- **迟到确认**：每次发送前排空陈旧 `+`；一次迟到的 `+` 满足当前等待后立即
  继续，不会错配到后续交换。
- **裸中断字节** `0x03`：在帧之外识别为中断，用于打断运行中的目标。
- **NoAckMode**：`QStartNoAckMode` 成功后双方关闭确认（测试同时覆盖两种模式）。
- 所有线路写都经过同一把写锁，读侧回送的 `+/-` 绝不会与数据包字节交错。

### 2.2 命令集（`pkg/protocol/packet.go`）

| 报文 | 含义 |
| --- | --- |
| `qSupported:...` | 能力协商，仅回显服务端支持的特性（见 2.3） |
| `QStartNoAckMode` | 关闭确认模式 |
| `?` | 查询最近停止原因 |
| `g` / `G<hex>` | 读 / 写全部寄存器 |
| `p<n>` / `P<n>=<hex>` | 读 / 写单个寄存器 |
| `m<addr>,<len>` / `M<addr>,<len>:<hex>` | 读 / 写内存（写为整段原子校验） |
| `s[;addr]` | 单步一条指令 |
| `c` | 继续（异步：先运行，停止后才回停止回复） |
| `Z0,addr,kind` / `z0,addr,kind` | 软件断点设置 / 清除 |
| `qBpList`（扩展） | 查看断点地址与命中计数 |
| `D` / `k` | 分离（保留现场）/ 杀死（复位目标） |
| 其它未知/畸形报文 | `E14`（畸形报文）或空回复（不支持） |

停止回复：`S05` 命中断点、`S02` 被中断、`S00` 普通停止、`S0b` 故障、
`W00` 正常停机（halt）。

### 2.3 能力协商（一致 / 降级 / 拒绝）

- 服务端只提供 `swbreak+`（软件断点）与 `QStartNoAckMode+`。
- 客户端宣称的**未知特性被静默丢弃**（明确降级），只回交集。
- 客户端要求 `hwbreak+`（硬件断点）时，服务端**明确拒绝**
  （`CodeFeatureRejected`），因为本模型只仿真软件断点。

## 3. 目标镜像兼容范围

### 3.1 文件格式（本地可复现）

```
偏移 0   8 字节魔数 "RPROBE01"
偏移 8   uint32 LE 格式版本（当前 1）
偏移 12  uint32 LE JSON 载荷长度
偏移 16  JSON 载荷（entry / stripped / segments[] / symbols[]）
尾部     uint32 LE 载荷 CRC32-IEEE
```

段内嵌字节以 JSON/Base64 承载，布局经校验：段按地址排序、**互不重叠**、
不溢出 32 位地址空间、权限非零、非空。可用 `probe init-image` 生成，也可用
`target.WriteImage` 由测试直接构造（见各 `_test.go`）。

### 3.2 内存与权限

- 段权限为读 / 写 / 执行三类：`.text` 为 `R+X`，`.data` 为 `R+W`。
- 访问按**逐字节**权限与映射校验：读要求全段可读、写要求全段可写、取指
  要求可执行且 4 字节对齐。
- **任何失败操作都不产生部分修改**：写内存 / 写寄存器先完整校验范围，再
  一次性提交；越界与只读写入返回不同错误码。

### 3.3 被裁剪 / 缺少调试信息的镜像

- `stripped=true` 的镜像不含任何符号，但**仍可完全调试**：寄存器、内存、
  断点（按地址）、单步、继续全部可用。
- 仅在按名查符号时返回 `CodeSymbolNotFound`，不影响地址级调试。

### 3.4 虚拟目标机指令集（4 字节定长）

`[opcode, b1, b2, b3]`，立即数为 b2:b3 小端 16 位。包含 `nop/halt/movi/add/
sub/ld/st/jmp/bz/jmpi` 及非法指令 `ill`。取指 / 访存 / 跳转的对齐与权限
错误都会形成带结构化错误码的**故障停止**（`S0b`），故障后目标拒绝继续
执行，直到显式复位。

### 3.5 重复加载与断线重连视图一致

- 管理器对同名镜像只加载一次，重复 `Load` 返回**同一目标实例**，现场
  （寄存器 / 内存 / 断点）保持不变。
- `D`（Detach）只释放会话槽、保留现场，重连看到一致视图；`k`（Kill）释放
  会话并把目标复位到镜像入口。

## 4. 错误分类

所有错误都是结构化的 `target.Error{Code, Op, Detail}`，`Code` 为稳定的
机器可读编号，报文层据此编码为 `Exx`，测试按编号而非字符串断言。

| Code | 十六进制报文 | 含义 |
| --- | --- | --- |
| `CodeImageTooShort` | — | 镜像短于文件头 |
| `CodeBadMagic` | — | 魔数错误 |
| `CodeUnsupportedVersion` | — | 版本不支持 |
| `CodeBadChecksum` | — | 镜像 CRC 校验失败 |
| `CodeImageCorrupt` | — | 结构损坏（长度不符、JSON 非法、段非法等） |
| `CodeSegmentOverlap` | — | 段地址重叠 |
| `CodeAddressOutOfRange` | `E07` | 地址未映射 / 越界 / 跨段 |
| `CodeReadOnly` | `E08` | 写入只读（R-X）内存 |
| `CodeNotExecutable` | `E09` | 在不可执行地址设断点 / 取指 / 非法指令 |
| `CodeMisaligned` | `E0a` | 断点 / 取指 / 访存未按 4 字节对齐 |
| `CodeSymbolNotFound` | `E0b`* | 符号缺失（*报文按场景可能不同，测试以常量断言） |
| `CodeRegisterIndex` | `E0c` | 寄存器索引越界 |
| `CodeBreakpointLimit` | `E0d` | 超过断点容量上限（默认 4） |
| `CodeTargetRunning` | `E0e` | 目标运行中收到不允许的变更 / 冲突请求 |
| `CodeTargetHalted` | `E10` | 目标已停机 / 故障，拒绝再运行 |
| `CodeStepBudget` | — | 单次继续超过指令预算（确定性兜底，默认 1,000,000） |
| `CodeSessionBusy` | `E11` | 已有活动会话占用目标 |
| `CodeSessionClosed` | — | 会话已结束 |
| `CodeMalformedPacket` | `E14` | 报文畸形 / 字段无法解析 |
| `CodeTimeout` | — | ACK 超时或空闲超时 |
| `CodeFeatureRejected` | — | 能力协商被拒绝（如硬件断点） |

> 注：报文层还会对帧级校验错误回送 `-`（而非 Exx），触发对端重传。

## 5. 会话与断点生命周期

### 5.1 会话状态机

```
                 Attach 成功
   (无会话) ───────────────────▶ Active
                                   │  │
                          D / 断线  │  │ k
                       /空闲超时    │  │
                                   ▼  ▼
                              Detached   Killed
                          （保留现场，   （目标复位到入口，
                            可立即重连）   可立即重连）
```

- **单活动会话不变量**：`Attach` 在会话锁内判定，并发争用下恰好一个成功，
  其余立即得到 `CodeSessionBusy`/报文 `E11`（不排队、不错综执行）。
- **断线 / 超时收敛**：运行中连接断开会先请求目标停止（Interrupt）再 Detach，
  目标与会话状态收敛到“已停止 + 会话槽空闲”的确定终态，随后可立即重连。
- 空闲超时在帧层用单个 `select` 实现，不额外创建 goroutine，避免取消与
  到帧之间的数据竞争。

### 5.2 执行控制一致性

- **单步 `s`**：精确执行一条指令；落点是断点时报告断点。从某断点 PC 单步
  离开是透明的（不做继续前的断点预检查）。
- **继续 `c`**：若当前 PC 处有断点，立即报告断点（含累计命中数）；否则异步
  运行，直到断点 / halt / 故障 / 中断 / 指令预算耗尽。
- 再次从断点 PC 继续会**再次停在该断点**（标准语义：要越过请先单步或清除）。
- **中断 `0x03`**：运行中收到即确定性停止为 `S02`；`Resume()` 返回即保证
  `IsRunning()==true`（启动握手），`Interrupt()` 返回即保证已停止，无睡眠
  竞态。
- **运行中冲突请求**：继续未决期间，除 `0x03` 外的入站报文一律拒绝执行
  （记录拒绝原因），不会与正在进行的继续交错。

### 5.3 断点语义

- 断点按 4 字节对齐、地址必须可执行，容量默认 4。
- **设置幂等**：对同一地址重复设置返回同一断点（保留命中计数）。
- **清除幂等**：清除不存在的断点也成功。
- 超上限 → `CodeBreakpointLimit`，未对齐 → `CodeMisaligned`，
  不可执行 → `CodeNotExecutable`，运行中变更 → `CodeTargetRunning`，
  彼此可区分。
- 断点携带单调命中计数，可通过扩展 `qBpList` 查询。

## 6. 本地验证方法

无需任何硬件、外部调试器或网络服务。

### 6.1 运行全部测试（推荐带竞态检测）

```bash
go test ./... -race -count=1
# 稳定性压测：
go test ./... -race -count=20
```

测试覆盖（均为确定性，不用固定时长睡眠来断言；少量毫秒级轮询仅用于等待
goroutine 调度，断言只针对最终状态）：

- **畸形报文 / 校验失败 / 重传 / 半包 / 重复包 / 迟到确认**：`pkg/protocol`；
- **并发会话争用**（16 路并发 Attach 恰 1 胜）、**重复加载同视图**、
  **Detach/Kill 重连**、**运行中断线收敛**：`pkg/session`、`pkg/server`；
- **裁剪镜像仍可调试**、**只读写入**、**越界不部分写**、**断点边界**
  （上限 / 对齐 / 不可执行 / 幂等 / 命中计数）、**单步/继续/中断一致性**、
  **非法指令故障**：`pkg/target`；
- **端到端**（真实 TCP 回环）能力协商、寄存器 / 内存、断点、继续中断、
  第二会话 `E11` 拒绝、坏镜像启动拒绝、空闲超时收敛：`pkg/server`。

单测日志通过 `t.Logf` 打印**报文内容、会话状态（active/detached/killed）、
运行/停止状态与拒绝原因**（如 `reject running packet ... reason=target-running`、
`session rejected: ... code=17`）。

### 6.2 命令行端到端冒烟

```bash
go build -o ./probe ./cmd/probe

# 生成正常镜像与裁剪镜像
./probe init-image -out /tmp/sample.img
./probe init-image -out /tmp/sample-stripped.img -stripped

# 启动探针服务
./probe serve -image /tmp/sample.img -listen 127.0.0.1:7000
```

随后可用任意 TCP 客户端按 RSP 手工交互（需要回送 `+` 确认）。仓库开发过程中
使用的等价 Python 冒烟序列（寄存器/内存/只读写入/断点/单步/继续/中断/D）
已在端到端 Go 测试中等价覆盖，避免对外部解释器的依赖。

## 7. 设计取舍小结

- **用本地镜像 + 虚拟目标机代替硬件**：错误码、权限、对齐、预算全部可精确
  复现；故障是带结构化原因的确定停止，而非未定义行为。
- **原子性**：内存/寄存器写先校验后提交；执行状态迁移由目标互斥量串行化。
- **单会话 + 顺序命令循环**：从根上消除两个调试请求交错的可能；冲突请求
  被拒绝而不是排队执行。
- **可控时钟**：重传定时器有 `FakeClock`，测试用 `Advance` 驱动，不依赖
  wall-clock 睡眠。
